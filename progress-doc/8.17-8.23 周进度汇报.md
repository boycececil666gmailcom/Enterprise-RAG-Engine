* **Direct Users**: A 3-person R&D team consisting of HMI software engineers, system test engineers, and embedded graphics architects working across multi-variant vehicle programs (e.g., Kanzi UI, Drive Mode Selection animations, Instrument Cluster transitions).

  * **Start Point**: An engineer inputs a defect symptom, subsystem behavior, or requirement query.

  * **Knowledge Silo & Noise Elimination**: Replaced noisy vehicle project codes (e.g., `004T`, `232D`) with horizontal, standardized engineering themes (e.g., `"Drive Mode Selection (DMS) 3D Car Model & Animation"`).

#### 4. Weekly Progress Results & Evidence

This week focused on implementing the **Enterprise JIRA Knowledge Modeling Engine, Multimodal Vision Enrichment, ADF Custom Field Decoding, and Docker Stack Orchestration**:

* **Schema-Driven Knowledge Extraction**:
  * Formulated **`TicketKnowledgeModel`** enforcing `theme` (horizontal umbrella category), `rca` (root cause background), `resolution` (technical fix applied), and `has_valuable_information` (noise filter gate).

  * Eliminated redundant `SystemMessage` prompt layers, allowing the LLM to be guided directly by Pydantic JSON schema tool parameters (`structured_llm.ainvoke(ticket_context)`).

* **Vision LLM Batch Analysis**:
  * Implemented `_enrich_attachments` and `fetch_media_data_uri` using `httpx` to authenticate, download, and convert screenshots into Base64 Data URIs.

  * Inlined clean visual descriptions via `clean_attachment_tags`, replacing raw tags with `[Attachment: <filename> | Description: <desc>]`.
  * Filtered binary archives (`.zip`, `.tar`, `.gz`, `.7z`) via `is_archive`.
* **Atlassian Document Format (ADF) Decoder**:
  * Implemented `format_custom_fields` and `extract_node_text` to recursively parse nested ADF paragraph/text nodes and option dictionaries.
  * Injected high-value engineering fields (`Self Test Report`, `Root cause`, `Solution`, `Component`, `Introduced reason`, `Child Action`) directly into the first-pass `ticket_context`.

##### 4.3 Hybrid Vector Store Ingestion & Schema Alignment (`3.ingest_to_qdrant.py`)
* **Payload Key Alignment**:
  * Configured `content_payload_key="small"` in `3.ingest_to_qdrant.py` and `vector_db.py` to ensure vector store payloads strictly match the Small-to-Big retrieval standard.
  * Dense vector generation (Gemini Embeddings, 768d) paired with FastEmbed BM25 sparse vectors for hybrid semantic + keyword search.

##### 4.4 Containerized Infrastructure Orchestration (`infra/docker-compose.yml`)
