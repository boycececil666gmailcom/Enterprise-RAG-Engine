### 8.10-8.16 Weekly Progress Report (English Version)

---

#### 1. One-Sentence Accomplishment Definition

Targeting a **3-person R&D team that needs to simultaneously consult internal technical documentation and large private source code**, and addressing the core pain points of **scattered materials, fragmented document-code relation, and untraceable evidence** during complex R&D problem analysis, we built and validated the **RAPTOR 3-tier hierarchical tree indexing and hybrid vector store ingestion pipeline (Small-to-Big Retrieval + Gemini Dense & BM25 Sparse Hybrid Search)**, moving towards the target of reducing the **median single-issue investigation duration (Time to Position, TTP)** from **45 minutes (baseline)** to **under 22.5 minutes (at least a 50% reduction)**.

---

#### 2. Business Scenario & Process Boundaries

* **Direct Users**: A 3-person team of development/testing/architecture engineers involved in consulting internal tech docs (Kanzi Engine & Studio), analyzing private source code, and conducting historical troubleshooting.
* **Process Owner**: Technical Leader / Knowledge Asset Lead of the R&D team.
* **Business Scenario**: When engineers troubleshoot complex subsystem bugs, verify API specifications, or conduct architectural refactoring, they need macro-level guidance (Layer 0/1 module overviews) down to micro-level implementation details (Layer 2 code snippets and Markdown specifications).
* **Process Boundaries**:
  * **Start Point**: An engineer inputs a complex technical query or error trace to look up specifications and code logic.
  * **End Point**: The system retrieves accurate macro/micro context chunks and provides citeable doc evidence and code references to verify root causes.
* **Core Bottlenecks Resolved This Week**:
  * Eliminating embedding space distortion caused by artificial metadata header noise in vector search.
  * Resolving the trade-off between retrieval precision and generation context via Small-to-Big architecture (`small` for vector similarity + `markdown` for LLM context).
  * Achieving high-efficiency hybrid recall via Gemini Dense (768d) and FastEmbed BM25 Sparse embeddings.

---

#### 3. Baseline Status & Verification Metrics

**Metric 1: Time to Position (TTP) per Single Issue**
* **Measurement Logic**: Median duration from initiating retrieval to finding the first set of accurate evidence (doc + code).
* **Data Source**: Log statistics / sampling from R&D efficiency pilot group.
* **Coverage Period / Sample Size**: 2026.07 / N=20 historical cases.
* **Current Baseline**: ~45 min.
* **Target Value (Next Phase)**: ≤ 22.5 min.
* **Status**: In verification pipeline.

**Metric 2: Top-5 Recall Rate (Recall@5)**
* **Measurement Logic**: Ratio of Top-5 retrieval results containing the target correct Chunk / code snippet.
* **Data Source**: Ragas automated evaluation dataset based on Kanzi docs.
* **Current Baseline**: Calculating on newly ingested Qdrant collection.
* **Target Value (Next Phase)**: ≥ 85%.
* **Status**: Ingestion completed; evaluation scripts queued.

**Metric 3: Table / Code Snippet Structural Integrity**
* **Measurement Logic**: Proportion of recalled results where tables and code blocks maintain uninterrupted semantics without contextual loss.
* **Data Source**: Expert manual sampling evaluation (50 complex blocks).
* **Current Baseline**: < 30% (Traditional naive slicing).
* **Target Value (Next Phase)**: ≥ 95% (Post Small-to-Big decoupled structure).
* **Status**: Verified in generated 4,517 chunks.

#### 4. Weekly Progress Results & Evidence

This week focused on implementing, standardizing, and verifying the **RAPTOR 3-Tier Tree Pipeline, Small-to-Big Retrieval Schema, and Qdrant Hybrid Ingestion**:

##### 4.1 RAPTOR 3-Tier Hierarchical Pipeline (`2.raptor_tree_pipeline.py`)
* **3-Tier Tree Construction**:
  * **Layer 0 (Root Global Summaries)**: 3 high-level entry documents providing global framework context.
  * **Layer 1 (Section Summaries)**: 58 intermediate topic summaries providing category-level context.
  * **Layer 2 (Leaf Detail Chunks)**: 4,456 semantic Markdown chunks split by `H1 > H2 > H3` and recursive character splitter (900 chars / 120 overlap).
  * **Total Dataset**: 4,517 structured chunks generated into standard delivery file `2.raptor_chunks.json`.
* **Small-to-Big Architecture Standardization**:
  * Standardized the retrieval property to **`small`** (concise summary for Layer 0/1, clean chunk for Layer 2) to eliminate metadata noise in vector spaces.
  * Preserved complete original page and chunk markdown under **`metadata.markdown`** for lossless LLM context injection.
  * Cleaned redundant `summary` fields from metadata to optimize payload storage.

##### 4.2 Qdrant Hybrid Batch Ingestion (`3.ingest_to_qdrant.py`)
* **Hybrid Embedding Integration**:
  * Dense: Google Generative AI Embeddings (`gemini-embedding-001`, 768 dimensions).
  * Sparse: FastEmbed BM25 Sparse Embedding (`Qdrant/bm25`).
* **Batch Ingestion Engine**:
  * Implemented robust batch ingestion (Batch size = 64) with deterministic UUIDv5 tracking.
  * Configured `content_payload_key="small"` in `QdrantVectorStore` to align database payload keys with the Small-to-Big schema.

##### 4.3 Backend Multi-Layer RAPTOR Retriever (`raptor_retriever.py`)
* **Flexible Retrieval Modes**:
  * **Collapsed Tree Search**: Default simultaneous multi-layer hybrid search across Layers 0, 1, and 2.
  * **Layer-Specific Filtered Search**: Targeted filtering via `raptor_layer` payload metadata (Layer 0 macro overview, Layer 1 section summary, Layer 2 leaf procedure).
  * Returns structured results containing `small`, `markdown`, `layer`, `layer_name`, `breadcrumb`, and `url`.

##### 4.4 Delivery Evidence
* **Data Output**: `preprocessing-pipeline/2.raptor_chunks.json` (4,517 validated chunks).
* **Code Implementation**: Decoupled, production-ready scripts `1.scrape.py`, `2.raptor_tree_pipeline.py`, `3.ingest_to_qdrant.py`, and `src/theme_based_rag_backend/raptor_retriever.py`.

#### 4. 本周项目推进结果及相关证据

本周重点完成了 **RAPTOR 3 层树形切片管道、Small-to-Big 架构标准化及 Qdrant 混合向量入库** 的全流程落地与代码重构：

##### 4.1 RAPTOR 3 层分层树管道建设 (`2.raptor_tree_pipeline.py`)
* **3 层树形拓扑结构构建**：
  * **Layer 0（Root 全局总览层）**：3 篇根级核心索引文档，提供框架全局宏观概览。

  * **Layer 2（Leaf 细节叶子层）**：4,456 个细粒度语义切片，基于 `H1 > H2 > H3` 标题与递归字符分块（900 字符 / 120 重叠）。

  * 移除 `metadata` 中冗余的 `summary`，精简 Qdrant Payload 存储开销。

##### 4.2 Qdrant 混合向量批量投递引擎 (`3.ingest_to_qdrant.py`)

  * 在 `QdrantVectorStore` 中显式指定 `content_payload_key="small"`，实现向量库 Payload 与 Small-to-Big 规范的完全对齐。

##### 4.3 后端分层 RAPTOR 检索器 (`raptor_retriever.py`)
* **多层检索模式支持**：
  * **Collapsed Tree Search**：默认对 Layer 0、1、2 进行同时混合搜索与融合。
  * **Layer-Specific Filtered Search**：支持通过 `raptor_layer` 元数据进行指定层过滤检索。
  * 统一返回包含 `small`, `markdown`, `layer`, `layer_name`, `breadcrumb`, `url` 的结构化字典。
